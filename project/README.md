# توزيع المهام على آلات غير متطابقة

نبحث عن إسناد كل مهمة إلى آلة واحدة لتقليل زمن انتهاء آخر آلة. يفترض النموذج وصول المهام كلها عند الزمن صفر، وعدم مقاطعتها، وعدم وجود أسبقيات أو أزمنة إعداد. البيانات تجريبية مولدة، ووحدة زمن المعالجة افتراضية.

## التشغيل

استخدم Python 3.12 أو أحدث، ومن مجلد project نفذ:

```text
python -m pip install -r requirements.txt
python main.py
python verify.py
```

تجربة قصيرة تكتب في مجلد مستقل:

```text
python main.py --runs 2 --output ../trial_results
```

إعادة أول تشغيلة لكل خوارزمية ولكل مسألة، مع فحص سجل التقارب كاملا:

```text
python verify.py --rerun
```

## الخوارزميات والتجربة

GA تعمل على متجه إسناد صحيح. PSO تستخدم درجة حقيقية لكل زوج مهمة وآلة، ثم تختار الآلة صاحبة أعلى درجة؛ ولا تقرب رقم آلة مستمرا. ACO تختار الآلات بحسب الفيرومون والحمل المتوقع بعد إضافة المهمة.

تحتوي التهيئة في الخوارزميات الثلاث على الحل الجشع نفسه. تحتوي الجماعة على 40 حلا، وتنفذ 120 تكرارا بعد التهيئة، أي 4840 تقييما للمرشحين في كل تشغيلة. الإعدادات الفعلية في settings.json، ولا يدعي المشروع أنها أفضل إعدادات ممكنة.

الأحجام هي 30 مهمة و4 آلات، و100 مهمة و8 آلات، و300 مهمة و12 آلة. لكل حجم ثلاث مسائل مستقلة. تكرر الخوارزمية عشرين مرة للمسألة بثوابت مسجلة، أي 540 تشغيلة في التجربة الكاملة. الفرز يحسم التعادل بالفهرس.

## الحد الأدنى وجودة الحل

يحسب lower_bound استرخاء خطيا باستخدام scipy.optimize.linprog: يسمح بمتغيرات إسناد كسرية مؤقتا ويقلل أكبر حمل. نتيجة هذا الاسترخاء حد أدنى، وتجمع مع حد أكبر زمن أدنى لمهمة منفردة، ثم تقرب بصورة محافظة إلى عدد صحيح. يستخدم الاسترخاء للمقارنة فقط؛ إسنادات الخوارزميات الثلاث صحيحة وغير كسرية.

Gap هنا هو 100 × (Cmax - LB) / LB. وهو فرق عن الحد الأدنى، ولا يساوي بالضرورة الفرق عن الحل الأمثل إذا كان الحد غير محكم. مساواة Cmax للحد تثبت الأمثلية لهذه المسألة. أما أفضل حل ظهر في التجارب فلا يسمى حلا أمثل دون هذا الدليل.

هدف التقارب هو Cmax <= 1.01 × LB. يحفظ الوصول في target_reached، ويترك target_iteration فارغا عند عدم الوصول. متوسط تكرار الوصول يحسب للناجحة فقط ويعرض بجانب عددها. التكرار صفر هو التهيئة. الانحراف المعياري يحسب داخل كل مسألة مع ddof=1 ثم يؤخذ متوسط المسائل الثلاث.

## الملفات

| الملف | المحتوى |
|---|---|
| scheduling.py | بيانات المسألة وحساب الأحمال والحل الجشع والحد الأدنى |
| algorithms/ | تنفيذ GA وPSO وACO |
| main.py | التجارب والرسوم وحفظ النتائج |
| verify.py | فحص البيانات والإسنادات والحدود والسجلات والملخصات |
| settings.json | الإعدادات الثابتة المستخدمة |
| results/processing_times.csv | زمن كل مهمة على كل آلة، والفهارس تبدأ من صفر |
| results/instances.csv | حجم المسألة وثابتها وحدها الأدنى وقياسات Greedy |
| results/all_runs.csv | قيمة وزمن وهدف التقارب لكل تشغيلة |
| results/summary.csv | متوسطات المقارنة حسب الحجم والخوارزمية |
| results/assignments.npz | الإسناد النهائي لكل صف في all_runs |
| results/histories.npz | أفضل Makespan عند كل تكرار |
| results/environment.json | الإصدارات وبيئة التنفيذ وبصمات الكود والإعدادات |

الرسوم تعرض التقارب وتوزع الفجوة والزمن وذاكرة التتبع، إضافة إلى أحمال الآلات في المسألة الكبيرة الأولى. الزمن مقاس خارج تتبع الذاكرة. الذاكرة ذروة tracemalloc في تشغيل إضافي بأول ثابت لكل مسألة، ثم متوسط المسائل، بوحدة KiB؛ وهي لا تشمل كامل ذاكرة العملية. الأزمنة وذروات القياس قد تتغير حسب الجهاز.
